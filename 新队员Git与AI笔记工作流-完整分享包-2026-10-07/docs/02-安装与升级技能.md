# 2. 安装与升级技能

技能决定笔记怎样写；全局规则决定什么时候询问是否生成。只复制 SKILL.md，不添加收尾规则，可能还需要每次主动要求归档。

## Windows 脚本安装

在本包目录打开 PowerShell：

```powershell
# 先看操作范围，不修改文件
.\install.ps1 -VaultPath 'D:\Obsidian\AI项目知识库' -WhatIf

# 首次安装
.\install.ps1 -VaultPath 'D:\Obsidian\AI项目知识库'

# 从旧版升级：保留已有配置，显式指定的新库路径会更新 vault_path
.\install.ps1 -VaultPath 'D:\Obsidian\AI项目知识库' -Update
```

路径换成你自己的。遇到组织的脚本执行限制，可交给 Codex 或手动安装，不需要为本包更改系统执行策略。

脚本安装到 `CODEX_HOME`，未设置时使用用户目录的 `.codex`。已有非空 `AGENTS.override.md` 时更新该文件，否则更新 `AGENTS.md`。升级时备份原技能和有效全局指令，只替换本工作流标记区块，保留其他指令与配置项。

脚本不会为你安装 Git 插件、创建远程仓库或上传笔记，这些在后续步骤单独完成。

## 手动安装（跨平台）

1. 找到 Codex 配置目录：默认 `~/.codex`，设置了 `CODEX_HOME` 则以它为准。
2. 复制 `obsidian-project-notes` 文件夹到配置目录的 `skills/`。
3. 修改安装后的 `settings.json`：

```json
{
  "vault_path": "D:\\Obsidian\\AI项目知识库",
  "note_subfolder": "AI 项目笔记",
  "timezone": "Asia/Hong_Kong",
  "language": "zh-CN"
}
```

Windows JSON 路径用双反斜杠；macOS/Linux 使用 `/`，例如 `/Users/用户名/Documents/AI项目知识库`。

4. 将 `global-instructions.md` 追加到有效全局指令文件；不要覆盖已有内容。如果已有本工作流区块，备份后只替换 BEGIN/END 标记之间的部分。
5. 开启新 Codex 聊天，问：“请说明我的 Obsidian 项目收尾规则，并检查技能的库路径。”

手动升级时保留原来的 settings.json，仅更换 SKILL.md 与模板，并审阅新的全局规则；不要用分享版的空库路径覆盖个人配置。

## 实际使用

项目结束时会询问一次，可选择：

- **生成并保存：**生成笔记，检查后保存，更新索引。
- **先给我预览：**先审阅内容，确认后才写入。
- **这次不用：**跳过本阶段，不反复催问。

也可主动说“项目完成了，生成 Obsidian 笔记”。笔记面向没有参与对话的人，包含背景、目标、成果与使用方式、流程图、关键决策、验证、限制和下一步；必要复现细节放附录。

库在当前 Codex 工作区外时，系统可能要求文件写入批准；归档确认与系统文件权限是两件事。一次归档选择不等于自动获得所有路径的长期写入权限。

## 可选：让助手处理后续 GitHub 测试

向 Codex 明确说：“请创建自动同步测试笔记，约五分钟后只读验证本地和 GitHub，不要手动提交或推送。”检查结果应区分未提交、已提交未上传、远程验证成功、网络导致无法验证。

官方说明：[Codex 如何加载全局与项目指令](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。项目自己的指令可能覆盖全局偏好；旧聊天未加载新规则时开新聊天。
