# 组规与协作规范（SRT 多电机协同控制）

> 组长：沈修竹。本文件是协作的「宪法」，所有组员遵守；改规则需组长同意。
> 配套：组会/评审会模板见 `docs/meetings/README.md`；验收口径见 `docs/acceptance_metrics.md`。

## 1. 角色与分工（4 岗，不写人名，组员认领岗位）
- **电控-仿真**：跑仿真全链路、Simulink 四电机、四策略复现、刚度扫描、鲁棒性验证
- **电控-理论**：系统课深学、`control_scheme.md` 推导、出图归档、报告电控章、答辩
- **机械-建模**：CATIA 建模、测惯量 J/B、机构简图、`plant_model.md`
- **机械-选型**：联轴器选型、查 `Ks`、算 `ω_n`、`Ks/Ds` 终值、`motor_params.xlsx`
- **组长（沈修竹）**：统筹进度、接口对齐、导师/师兄对接、判定验收、最终拍板

## 2. Git 与分支规范（防翻车）
- 每人建分支 `feature/岗位-周次`（如 `feature/电控-仿真-W6`），**禁止直接在 main 上推**
- **禁止 `git push --force`**（会覆盖别人历史，曹磊事件教训）
- **禁止在别人分支上乱改**；要改先提 PR 或群里说一声
- PR 必须组长 review 通过才合；合之前仿真能跑通、周报填好
- 每天开工先 Pull，收工再 Commit+Push；冲突截图发群，别自己憋

## 3. 命名规范
- 文档/图/数据统一前缀：`W{周}_{策略}_{指标}`（例：`W6_主从_同步误差.png`）
- 周报文件名：`周报_W{周}_{岗位}.md`，用 `Formal Written Report/组员周报提交表.md` 格式
- 仿真结果图命名见 §4

## 4. 仿真结果与数据留存规范（写论文 / 专利用）
- 目录：`data/results/`（建好即入库，不散落桌面）
- 图命名：`fig_W{周}_{策略}_{指标}.png`（例 `fig_W10_刚度扫描_同步误差RMS.png`）
- **重要数据留档**：每阶段关键仿真结果存 **csv + 元数据 json**（参数、工况、脚本版本），不只留截图
- 哪些算「重要」：四策略对比图、刚度扫描曲线、鲁棒性 PASS 结果、每轮迭代指标——以后写论文/申专利直接调
- 大文件（CAD/STEP）走 Git LFS，别直塞仓库

## 5. 提交与 Deadline
- 周报：每周五 22:00 前交，格式用 `组员周报提交表.md`
- 交付物：当周完成当周交，别攒到月底
- 进度落后：任务后移、砍学习深度，**永远不砍交付物**（表/参数/模型/报告）

## 6. 组会与请假
- 周会：每周固定 30 分钟（建议周日晚），议程见 `docs/meetings/README.md`
- **请假**：提前在群里说，并找同组伙伴代进度；缺席当周任务下周补齐
- **缺席**：无请假缺席 → 组长私聊提醒，连续两次在周报点名
- **月末长会：不做**（避免形式主义，用户定）

## 7. 决策与升级
- 接口分歧（机械说 `Ks` 够 / 电控说不够）：**拿数据说话**，周会定
- 周会定不了 → 组长拍板；仍僵 → 找导师（组长负责约）

## 8. 署名
- 论文 / 专利 / 结题证书名单顺序**提前写死**（组长定，避免后期撕）
- 贡献按岗位记录，周报即证据

## 9. 外援节点（组长负责，不占组员时间）
- **找师兄**：W4（参数测量对不对）、W6（联轴器选型经验）、W9（联合仿真踩坑）
- **找导师说清的点**：W8 中期方向、W10 创新点方向、寒假申报书框架、Q4 结题/专利方向
- 组长主动约、记录、转达给组员
