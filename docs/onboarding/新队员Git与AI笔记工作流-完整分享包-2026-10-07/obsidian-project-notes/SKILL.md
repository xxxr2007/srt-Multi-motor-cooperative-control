# Obsidian 项目笔记

读取同目录的 `settings.json` 获取库路径与保存目录。路径未配置时，先询问用户；不能自行选用检测到的库。用户批准生成前不向库写入笔记。用户明确说“生成笔记”“保存到 Obsidian”即为本次授权，无需再次确认。

## 内容与阅读体验

- 面向没有参与对话的读者，用简体中文先讲项目解决什么问题、取得什么成果、如何使用。专业术语首次出现时用一句话解释。
- 根据可访问的对话与成果文件整理，覆盖目标、背景与约束、最终方案、关键决策及原因、主要工作流、产物、验证、限制和下一步。未访问的历史或未验证的结果必须标明，不能为追求完整而补造。
- 正文通常约 800–1800 中文字；简单任务可更短，复杂项目按覆盖情况扩展。正文呈现最终方案，影响结果的试错浓缩为经验；必要的复现细节放入折叠附录。
- 用 Mermaid 流程图、架构图或时序图解释最重要的关系。图下添加简短说明，保证不看图也能理解。已有截图、图表或成品预览确实有解释价值时，将授权可复制的本地素材复制到库内附件目录，使用相对路径嵌入并写图注；不得以概念图冒充实际结果。没有截图时使用流程图即可，不虚构截图。
- 不倾倒聊天记录、日志或完整代码。保留能帮助复现的命令、参数和简短代码；只在有可用地址时链接原始对话。对读者必需的材料复制入库或说明获取方式，不能仅依赖作者机器上的绝对路径。
- 不写入密码、令牌、私钥及与项目无关的个人信息。区分已完成、已验证、待验证和待办。

## 保存

1. 按 `note_subfolder/YYYY/` 存放笔记，日期使用 settings.json 中的 timezone，默认 Asia/Hong_Kong。文件名用 `YYYY-MM-DD-项目名称.md`，移除 Windows 非法字符。同名时先检查是否为同一项目；没有更新授权时添加 `-02` 等后缀，不覆盖已有内容。
2. YAML 属性包含 `title`、`date`、`updated`、`status`、`tags` 和可用的 `source`；字段值正确引用，不使用不存在的对话地址。`status` 反映项目本身而不是笔记保存状态。
3. 正文参考同目录 `note-template.md`，删除不适用部分，不遗留占位符。附件位于 `note_subfolder/_attachments/笔记名称/`；嵌入使用笔记到附件的相对路径。
4. 保存前检查所有实际读取的来源是否支持结论、章节是否覆盖主要信息、图片是否存在、链接是否可用。保存后读回文件并检查 YAML、代码围栏和本地附件引用。可用时在 Obsidian 预览验证图文；没有实际渲染就说明只完成文件级检查。
5. 新文件追加到 `note_subfolder/索引.md`，使用库内相对 Markdown 链接，避免重复条目，不重写用户已有索引内容。
6. 返回笔记的绝对路径链接、笔记内容的简短说明和任何未验证事项。若库目录不在可写范围，请通过正常执行审批申请准确的文件写入权限，不绕过权限；未获准时在当前工作区保留草稿并报告未入库。

本技能生成的是项目知识笔记，而非完整聊天备份。若上下文不足，注明覆盖范围，或让用户提供缺少的关键背景。

## 库迁移与 GitHub 同步

初次配置建议使用独立 Obsidian 库，不放入其他项目的 Git 仓库；已有库迁移时校验笔记、附件和索引后再移除原目录，并更新已安装技能的 settings.json。用户指定现有库时先遵循其选择，再解释发现的项目混入问题。

本技能负责生成和保存，不默认提交或推送。用户已配置 Obsidian Git 时，让插件处理后续同步。不能把“已保存”“已提交”“已上传”混为一谈，也不能承诺五分钟内必定成功。

用户要求验证自动同步时，创建含唯一标记的测试笔记后只读检查，不能自行提交或推送替代插件。核对实时远程提交中的文件和标记；只有本地提交或旧的 origin/main 引用不足以证明上传。网络失败时标明无法验证。
